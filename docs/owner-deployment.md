# Owner account deployment

The optional owner deployment uses one server-verified account and any number of registered browsers and Windows 11 x64 connectors. The standard pairing deployment remains available when ACCESS_MODE is unset.

Set ACCESS_MODE=owner, PUBLIC_ORIGIN, OWNER_SUB, IDENTITY_BASE_URL, FRIBENCH_CLIENT_SECRET and SESSION_BINDING_KEY on the relay. The identity backend implements Fribench application sessions, desktop PKCE grants and account-state verification. Keep deployment secrets in the private operations configuration. Browser and connector sockets use /ws/browser and /ws/connector with protocol 5. A valid account and browser device proof are both required. Existing protocol 4 PC routes can be pinned by LEGACY_PC_KEY_ID, LEGACY_PC_ROUTE_ID and an explicit LEGACY_PC_UNTIL during migration. Legacy routes cannot carry browser commands.

The public home page links to /download. One Windows x64 package per release contains Node, compiled connector code and native image dependencies. Each installation creates or preserves its local device identity. The current Windows user signs in through the system browser and confirms the PC fingerprint. The settings window shows the device, connection and installed version. Sign in through the default browser or check for an update and confirm installation. After Windows sign-in, the Connector runs independently of the settings window and retries lost connections. Owner sessions and downloads can use paths accessible to the signed-in Windows account without selecting project roots. Codex execution approvals are independent.

The release directory holds a signed stable.json and immutable versioned installers. The package includes a pinned release.pub. The updater verifies the Minisign manifest and installer SHA-256 before execution. The installer uses a per-user task, a version pointer and startup verification. Account authorization and network connectivity are reported separately from local startup health.

Browser themes follow the system by default, with light and dark overrides. Conversation history can appear before the live-state request finishes. Opening a conversation subscribes that browser to the connector-owned task events. Device revocation closes its current sockets and blocks its old application session from private HTTP routes.

The owner interface uses shared neutral surface, text and status roles for white and charcoal themes. Download, account, device management and appearance controls sit below the session list. Chat controls retain their original positions. Messages use 16 px text, quiet user bubbles and unboxed assistant replies. The standalone download page follows the system theme and lists the Windows and Codex Desktop requirements.

The Windows release build converts PowerShell scripts to UTF-8 with BOM for Windows PowerShell 5.1. Build on Windows x64, bundle production dependencies and the matching Node executable, and use NSIS with scripts/connector.nsi. The build directory must include connector-release.json and release.pub. Source and web builds remain npm run build. Run npm run check for the repository checks and the owner access tests for account/device changes.

Release 0.5.0-fribench.3 bundles only the Connector entry points and sharp's native runtime dependency graph. Node is still included. Use a fresh external output directory with scripts/build-owner-connector.ps1. The optional SignTool and SigningCertificateThumbprint arguments add Authenticode signing after packaging; without a trusted certificate, Windows or the browser may still warn about an unknown publisher. Minisign authenticates updates but does not establish Windows publisher reputation.

The Chinese setup extracts into a unique staging directory before stopping an idle Connector. Same-version reinstall moves the old version into a rollback directory, activates the complete payload and verifies the running installation path and settled version pointer. Settings and DPAPI identity remain outside version directories. Shortcuts launch the settings window without a command console. Scheduled-task failure uses the same hidden login-start entry for normal startup and recovery. Existing-version recovery explicitly activates that version. Only unreferenced installer-generated repair backups are cleaned after health succeeds. Windows PowerShell status probes decode UTF-8 explicitly, including Chinese user paths. Run scripts/test-connector-install.ps1 under Windows PowerShell to verify isolated first install, same-version repair, upgrade, rollback, identity preservation and UTF-8 paths.

Transient identity failures close the socket with retryable 1013, login expiry uses 4401, and confirmed device revocation uses 4403. Expired leases cannot route commands. Interrupted identity responses release shared checks so reconnects can recover. Account checks and device dialogs discard stale responses. The quota control retains the spinning run indicator, reads account/rateLimits/read on the selected PC and displays only the Codex bucket in its summary. Other returned pools appear separately in the detail view. Missing data is shown as unavailable, rather than as a guessed percentage.

Native clipboard images in history carry their local-image source so previews use the correct reader; the source path stays on the selected PC. Standalone internal goal messages are hidden in the timeline while original conversation data remains intact. Desktop permission controls are read-only, and nonfunctional open-on-computer buttons are removed. Session dots use blue for running and green for completed-unread. Browser theme-color and color-scheme metadata follow the chosen theme; native host browser chrome may impose its own appearance.

Image cards and image previews also offer Save image. This reads the original through the resumable file-download protocol, then opens a separate original-image panel. A fresh click shares the image file through the OS share sheet; on iPhone the user chooses Save Image. Unsupported sharing falls back to touching and holding the original image or downloading the file. PNG, JPEG and WebP bytes are preserved, with MIME detected from the original header rather than the compressed chat preview. Dismissing the share sheet is not reported as a failed save, and the page does not claim that the OS saved a photo. Changing the selected session or PC clears the prepared image. The initial share dialog shipped as a web-only update for .3.

Release 0.5.0-fribench.4 retains uploaded conversation images in `%USERPROFILE%/.codex-anywhere/attachments`. Installation copies remaining legacy uploads there. Old temporary paths in history can still resolve after Windows clears the originals. The save action reads the image immediately, and transfer errors and retries stay with the attachment. Normal account binding survives reinstall; an interrupted approval can be retried in the same browser. The PC shows separate sign-in and update actions. The scheduler or its login fallback launches a supervisor that restarts a failed worker.

Desktop session headers can show direct subagents and a return link to their parent using local Codex relationship metadata. The composer offers an editable follow-up when the last assistant message explicitly identifies a next step. Tap the suggestion or press Enter in an empty composer to accept it. Sending uses the existing send action. This uses conversation text locally and makes no separate prediction request.

Release 0.5.0-fribench.2 starts the background Node process through ProcessStartInfo with independently drained stdout and stderr. This avoids Windows PowerShell 5.1 treating native stderr as a terminating error. The per-user scheduled task supervises the versioned process. The local startup probe verifies the installed version, while the connector status reports account/network connectivity separately. Connector updates drain connector-owned turns and file transfers. ## Fribench account mode

Set `ACCESS_MODE=account` and `ACCOUNT_ADMISSION=owner` to verify the existing account on the new data format. Switch admission to `all` after two-account isolation and existing-device checks pass. Account mode uses the Fribench account ID from the identity proxy. Device names and routes are private to that account. A Connector identity stays bound to one account. The browser may use a different Fribench account after explicit reauthentication.

Run `docker compose run --rm --no-deps bridge build/server/migrate-accounts.js` with the new image, the existing device volume and the original `OWNER_SUB` after stopping the old Bridge and taking its backup. The migration preserves existing browser and Connector identities and revocations. The server uses `accounts.v2.json` and leaves the v1 files available for the release rollback. Keep one Bridge writer and retain the original `SESSION_BINDING_KEY`. To suspend wider access after launch, restore `ACCOUNT_ADMISSION=owner` on the v2 release.
