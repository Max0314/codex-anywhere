# Owner account deployment

The optional owner deployment uses one server-verified account and any number of registered browsers and Windows 11 x64 connectors. The standard pairing deployment remains available when ACCESS_MODE is unset.

Set ACCESS_MODE=owner, PUBLIC_ORIGIN, OWNER_SUB, IDENTITY_BASE_URL, FRIBENCH_CLIENT_SECRET and SESSION_BINDING_KEY on the relay. The identity backend implements Fribench application sessions, desktop PKCE grants and account-state verification. Keep deployment secrets in the private operations configuration. Browser and connector sockets use /ws/browser and /ws/connector with protocol 5. A valid account and browser device proof are both required. Existing protocol 4 PC routes can be pinned by LEGACY_PC_KEY_ID, LEGACY_PC_ROUTE_ID and an explicit LEGACY_PC_UNTIL during migration. Legacy routes cannot carry browser commands.

The public home page links to /download. One Windows x64 package per release contains Node, compiled connector code and native image dependencies. Each installation creates or preserves its local device identity and allowed directories. The current Windows user signs in through the system browser and confirms the PC fingerprint. The local settings window can add project roots and request an update. Existing conversations and supported linked previews retain their original reading rules. New conversations and ordinary file downloads use the roots selected on that PC.

The release directory holds a signed stable.json and immutable versioned installers. The package includes a pinned release.pub. The updater verifies the Minisign manifest and installer SHA-256 before execution. The installer uses a per-user task, a version pointer and startup verification. Account authorization and network connectivity are reported separately from local startup health.

Browser themes follow the system by default, with light and dark overrides. Conversation history can appear before the live-state request finishes. Opening a conversation subscribes that browser to the connector-owned task events. Device revocation closes its current sockets and blocks its old application session from private HTTP routes.

The owner interface uses shared neutral surface, text and status roles for white and charcoal themes. Download, account, device management and appearance controls sit below the session list. Chat controls retain their original positions. Messages use 16 px text, quiet user bubbles and unboxed assistant replies. The standalone download page follows the system theme and lists the Windows and Codex Desktop requirements.

The Windows release build converts PowerShell scripts to UTF-8 with BOM for Windows PowerShell 5.1. Build on Windows x64, bundle production dependencies and the matching Node executable, and use NSIS with scripts/connector.nsi. The build directory must include connector-release.json and release.pub. Source and web builds remain npm run build. Run npm run check for the repository checks and the owner access tests for account/device changes.

Release 0.5.0-fribench.3 bundles only the Connector entry points and sharp's native runtime dependency graph. Node is still included. Use a fresh external output directory with scripts/build-owner-connector.ps1. The optional SignTool and SigningCertificateThumbprint arguments add Authenticode signing after packaging; without a trusted certificate, Windows or the browser may still warn about an unknown publisher. Minisign authenticates updates but does not establish Windows publisher reputation.

The Chinese setup extracts into a unique staging directory before stopping an idle Connector. Same-version reinstall moves the old version into a rollback directory, activates the complete payload and verifies the running installation path and settled version pointer. Settings and DPAPI identity remain outside version directories. Shortcuts launch the settings window without a command console. Scheduled-task failure uses the same hidden login-start entry for normal startup and recovery. Existing-version recovery explicitly activates that version. Only unreferenced installer-generated repair backups are cleaned after health succeeds. Windows PowerShell status probes decode UTF-8 explicitly, including Chinese user paths. Run scripts/test-connector-install.ps1 under Windows PowerShell to verify isolated first install, same-version repair, upgrade, rollback, identity preservation and UTF-8 paths.

Transient identity failures close the socket with retryable 1013, login expiry uses 4401, and confirmed device revocation uses 4403. Expired leases cannot route commands. Interrupted identity responses release shared checks so reconnects can recover. Account checks and device dialogs discard stale responses. The quota control retains the spinning run indicator, reads account/rateLimits/read on the selected PC and displays only the Codex bucket in its summary. Other returned pools appear separately in the detail view. Missing data is shown as unavailable, rather than as a guessed percentage.

Native clipboard images in history carry their local-image source so previews use the correct reader; this does not expand ordinary file-download roots. Standalone internal goal messages are hidden in the timeline while original conversation data remains intact. Desktop permission controls are read-only, and nonfunctional open-on-computer buttons are removed. Session dots use blue for running and green for completed-unread. Browser theme-color and color-scheme metadata follow the chosen theme; native host browser chrome may impose its own appearance.

Release 0.5.0-fribench.2 starts the background Node process through ProcessStartInfo with independently drained stdout and stderr. This avoids Windows PowerShell 5.1 treating native stderr as a terminating error. The per-user scheduled task supervises the versioned process. The local startup probe verifies the installed version, while the connector status reports account/network connectivity separately. Connector updates drain connector-owned turns and file transfers. Independent Codex Desktop turns continue under Desktop.
